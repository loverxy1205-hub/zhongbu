# 众卜 v2.0.1 · 算法与解释约定

本站不是预测模型，没有训练、准确率、置信度、成功概率或玄学评分。用途是文化体验与自我反思。十个可选篇章互不读取答案或用户偏好，默认选中原有塔罗、周易、梅花、数字和卢恩；新增五篇需要主动选择。应用版本为2.0.1，规则及模板仍为2.0.0，知识版本为2026.09.30-3；历史记录保留各自版本。

## 生命周期

`Input → calculate/draw → interpret → renderText → EngineResult → Reading`

上式适用于周易、梅花、数字和卢恩，以及旧版塔罗。v1.5 新记录由 `createJourney` 在显式提交事件创建，内部调用 `createReading(..., interactiveTarot=true)`；提交入口用同步 `ref` 锁防止双击。一次提交捕获一个 ISO 时间戳，生成由四个 uint32 组成的 readingId，深冻结公开输入（不含生日）、版本及已经完成计算的各体系结果。日期型引擎不注入随机扰动。

新塔罗的流程是 `提交 → 洗好并冻结完整78张牌及各牌正逆位 → pending → 用户依次选择3个不同槽位 → interpret/renderText → ok`。`SavedReading.tarotDeck` 保留预洗牌序，`tarotPicked` 保存实际选择的槽位（0–77）。未选满三张时没有塔罗原始三牌结果或解释；第三次选择才按选择顺序产生「现状／阻力／提示」，在同一 readingId 下替换唯一的 pending 塔罗条目并冻结新 Reading。其余体系、输入、版本、时刻不变。选择、揭晓、翻页、刷新和动画不使用随机数，不重新洗牌，也不修改已经完成的解释；选择重复或无效槽位被忽略。旧 `createReading` 调用默认仍直接抽三张，旧记录不迁移。

新增地占、咖啡、Ifá、掷筊、灼甲使用独立的 `src/experiences/<id>` 模块。创建记录时一次生成该篇章所需随机参数，版本化状态直接放入 `EngineResult.raw`，未完成时保留 `pending`。用户操作先经严格Zod校验和对应 `canTransition*` 验证，拒绝改写冻结参数、越级推进或回写旧记录；通过后只替换同一readingId的当前条目，其他结果不变。组件仅保存临时动画状态，不能在渲染或动画中抽取。

新增篇章完成后保存当时的 `Interpretation`，呈现冻结文本。咖啡每个观察版本第一次完成时，把解释和全部版本写入 `observationInterpretations` 缓存；切换旧观察直接读原解释，不按当前词典重新生成。缓存校验版本ID唯一、与已存观察对应及当前解释一致。灼甲追加事后记录只更新原始记录中的追加列表，保留完成时的旧解释。新增五篇无AI入口，也不通过共享模型契约。

`src/types.ts` 定义有判别字段的结果联合类型，没有无约束 any。`src/data` 是原五套知识，`src/engines` 负责计算，`src/experiences` 组织新增篇章的数据、状态机、解释和视图，`src/rules` 负责原五套解释与共享汇总，`src/lib` 管理存储及导出，`src/components` 呈现结果。

## 随机数

Web Crypto `getRandomValues(Uint32Array)`；均匀整数 `0..m-1` 使用拒绝采样：只接受小于 `floor(2^32/m)*m` 的值，再取模。无放回抽取使用部分 Fisher–Yates 洗牌。测试可注入 uint32 源。问题、生日、时间戳都不会成为随机种子。

## 塔罗

v1.6.1选牌期间，上方三槽恢复对应冻结牌ID的大图和正逆朝向；未选槽用同尺寸牌背占位，下方78槽仍在原位置翻牌。星河效果由少量背景星云、星轨实现，不移动命中区域、不拦截点击、不生成随机数；暂停／减少动态时静止，刷新仍对应原选择。

完整 78 张 RWS 名称：22 大阿尔卡纳、四花色各 14 张。强力／力量为 VIII，正义为 XI。三张依次是现状、阻力、提示。v1.2 新表单默认开启逆位，不提供开关；各张独立掷一次公平二值随机数，50% 逆位，这是本站约定。旧记录保持自身配置和结果。正逆位拥有分别整理的释义与主题。

v1.5 在提交时无放回洗出完整78张牌，为每张冻结一次正逆位。页面展示78个牌背，用户选择哪个槽位就得到该槽位预先确定的牌，三次选择顺序决定牌阵位置。不会用事先选好的三张牌替代任意点击位置。完成后不允许在同一记录中换牌；再问一次才新建记录与整副牌。记录恢复同时校验78张牌完整唯一、已选槽位不重复，以及完成后的三张牌与槽位对应关系。

位置模板独立：现状观察处境；阻力检视主题的不足、过度或牵制，不把它当直接行动建议；提示提供反思角度。人物牌不规定性别。死神象征收束更新，高塔象征原有结构被挑战，不指现实死亡或灾难。几何卡面为本站原创装饰，并非 RWS 商业牌图。

## 周易三枚铜钱

每轮三枚公平硬币，一面 2，另一面 3；v1.6 钱面显示约定为3=阳面刻乾隆通宝、2=阴面无字。这是本站美术约定，不声称复原古钱背面；抛掷最后落面与冻结币值对应。和值 6 老阴、7 少阳、8 少阴、9 老阳。八种等可能组合的计数为 1/3/3/1。六轮自下而上，字符串第 0 位是初爻，前三位为下卦，后三位为上卦。1 为阳，0 为阴。仅 6/9 翻转；画图反向遍历以保证上爻在上。

六轮结果仍在提交时一次生成并冻结。v1.5 的 `coinRounds` 从0依次推进至6；每次点击摇币只揭示下一轮的三币记录与爻值，同时从初爻开始向上画出一爻，六轮完成后开放本卦、动爻、变卦的解读与AI。跳过或减少动态效果只完成当前轮，不额外生成硬币，也不跳过剩余轮次。

64 卦编码完全唯一。并列阅读本卦卦辞、全部动爻、变卦卦辞；没有动爻时不伪造变化。保存乾坤用九／用六作为附录，本版不另外触发专门断法。未实现六爻纳甲、世应、六亲、择爻断法。

## 梅花年月日時

依据《梅花易數》卷一「年月日時起例」，使用**提交时冻结的问卜时刻**。浏览器 Intl 先转为用户指定的 IANA 时区当地公历年月日和小时，`lunar-typescript@1.8.6` 再转换农历。

Y 为农历年地支序（子 1 至亥 12），由农历年 `(year - 4) mod 12 + 1` 得到；不用公历年或立春年。M 为农历月绝对值，D 为农历日，H 为 `floor((hour+1)/2) mod 12 + 1`。

`R(n,m)=((n-1) mod m)+1`。上卦 `R(Y+M+D,8)`；下卦 `R(Y+M+D+H,8)`；动爻 `R(Y+M+D+H,6)`。八卦编号乾1、兑2、离3、震4、巽5、坎6、艮7、坤8。

样例 5、12、17、9：和 34/43；上兑2、下离3、初爻动。自下而上 `101110 → 001110`，革之咸。

工程约定：正月初一换年；闰月使用原月序数；零点换日；子时 23:00–次日01:00；不做真太阳时校正。采用本地民用日转换，未重新计算所选地理位置的新月。支持公历 **1901–2099**；超范围、无效时区、转换错误明确不可用。

动爻在初至三爻，下卦为用，上卦为体；四至六爻相反。五行：乾兑金、离火、震巽木、坎水、艮坤土。只比较比和、生、克；无旺衰、互卦、外应。周易与梅花属于相关体系，不是独立科学证据。

## 生日数字九宫格（新记录）

新数字结果使用 `kind: numerology-matrix`，引擎标识仍为 `numerology`，方法为「生日数字九宫格 v1」。取用户公历生日 `YYYY-MM-DD` 的原始数字，忽略 0 和分隔符，统计 1–9 的重复次数；不求数字根、不添加四工作数、不加入目标日期。布局按行依次为 **1/4/7、2/5/8、3/6/9**，不是洛书方阵。

例如 1998-06-15 得到 1×2、5×1、6×1、8×1、9×2，其余格留白。生日必须有效、在1901–2099支持范围且不晚于问卜时刻在所选时区的当地日。新算法不因目标日期早于生日而拒绝，也不会因为目标日期或再次提问改变图案。缺生日仅此体系不可用。

这是用户选择的「生日原始数字版」，本站以毕达哥拉斯式现代数字象征玩法呈现，不声称是毕达哥拉斯本人提出的算法，也不混入其他现代流派的工作数。每格含义为本站原创，次数不用于能力、人格、健康、智商、财富或命运评分，空格不表示缺陷。解释选取次数较多的至多两个数字作为主题，同次数按数字升序仅是确定的呈现顺序。点击各格只读取冻结数据，不重算。

冻结记录保存格数与方法，**不保存生日及原始数字顺序**。格数仍是生日派生的个人数据，并不保证匿名；完整本机记录和用户主动导出会包含格数。AI 请求不发送生日、完整格数、缺位集合或计算轨迹，只发送至多两个精选主题与冻结的象征释义。旧个人日记录与旧解释原样保留，恢复时不迁移或重新计算。

## 简化个人日（旧记录兼容）

本站现代规则：reduce 反复逐位相加至1–9，不保留11/22/33。

- 生命数字：出生日期所有数字之和再 reduce。
- 个人年：出生月 + 出生日 + 目标公历年份数字和，再 reduce。
- 个人月：个人年 + 目标月份，再 reduce。
- 个人日：个人月 + 目标日号，再 reduce。

个人日决定本次主要主题，其他数字作背景。缺生日只让该项不可用。生日不能晚于问卜当地日或目标日。生日及可反推出出生月日的中间加数不进入轨迹；生命数字等最终派生值会保留，这不等于匿名化承诺。

## 现代卢恩

24 Elder Futhark 符文，无空白符、无逆位，无放回抽三枚。名称采用现代常见学术重建写法，符号为 Unicode 对应字符，随包附 Noto Sans Runic 字体。三位置规则与塔罗共用结构，知识释义独立；不冒称统一的古代占卜法。

三枚符文仍在提交时冻结。v1.5 先显示布袋，每次点击让 `runeDrawn` 依次从0增加至3，摸出一枚未打开的石头；三石齐备后沿用逐块撬开的动画。`runeRevealed` 记录已打开的位置，三枚全部打开才显示本体系解读与AI。摸袋和撬石只揭示已冻结结果。

## 地占术·沙盘起占

采用基本十五位盾形图，完整16种图式按从上到下四行编码，单点为1、双点为0。不是风水、八卦或Ifá，不含十二宫断法和第十六调和图。图式表、左右位置及来源核对详见[地占说明](GEOMANCY.md)。

三种输入各自明确：手点每次点击或独立空格按键留下一个真实可见点，完成16行；实物录入16个1–999999的正整数；自动模拟在提交时冻结16个5–36均匀整数，奇偶等可能是本站工程约定。手点每行至少一个、最多128个，不根据拖动轨迹或按住时间暗增点。点的唯一ID和坐标、已确认行数均可恢复。

16行奇偶按顺序组成四母；四女是四母的转置。侄图依次为 `M1 xor M2`、`M3 xor M4`、`D1 xor D2`、`D3 xor D4`；两位证人为前两侄图与后两侄图各自异或，裁判为两位证人异或。每一步保留父图关系，逐层展开或单步查看不抽样。屏幕上排从左至右为D4、D3、D2、D1、M4、M3、M2、M1，右侧证人来自母图一侧，避免数组顺序替代盾图布局。解释取两位证人与裁判的关系，以本站现代反思文案呈现，不把十五个位置当十五票。

## 咖啡渣占·翻杯观纹

流程为留渣、轻转、盖碟、翻杯、沉淀、观察、记录。创建时冻结四个uint32；盖碟时由种子和已经确认的净转角／累计转动量确定98块矢量纹理（团块、流痕及周围细屑），之后观察版本共用同一纹理。确定性纹理不是流体力学复现；生成器不读取问题、符号词典或预选答案，不把藏好的鸟、环等轮廓伪称识别结果。

展开图使用杯柄为角度零点，纵轴从杯底到杯口；旋转、俯视和缩放只改变投影。用户先看图，再在原始展开视图框选或用键盘范围控件选区，明确选择意象和填写自己的观察。没有看见清楚形状是合法完成状态。杯底／杯壁／杯口按选区中心深度判定，仅是空间划分，不对应未经核实的时间预测。

本地20条词典全部标为「本站象征提示」。最多8个标注、8个观察版本；已完成观察只读，新观察仍引用同一纹理，解释首次完成即缓存。纹理参数、框选坐标和解释版本随记录保存，不存大体积base64。没有照片上传、自动识图或在线识别服务；可选的本地照片输入尚未实现。详见[咖啡说明](COFFEE.md)。

## Ifá·占链体验

仅实现òpèlè占链符号与资料体验，不等于包含受训解释者及口传诗节的完整Ifá宗教咨询，也不混用欧洲地占名称或ikin法。八枚链片提交时分别取一次公平二值，数字假设不是对真实占链分布的测量。器具说明、聚焦、提起、释放、落定、两列符号、资料阅读按固定状态推进。

采用已经核对的操作者视角：操作者位于画面下方，链顶在上；先读右列，再读左列，各自从上到下。凹面朝上为单划I，编码1；凸面朝上为双划II，编码0。16种基础四行图式配对覆盖256种有序签名（16同列、240异列），固定样例校验朝向与读取顺序；不将屏幕镜像当作传统约定。

`signatureCatalog`、`interpretationCorpus`、`reflectionTemplates`独立维护。组合名称未充分核实时只显示签名ID，不编造Yorùbá名称。本版传统解释语料为0，统一明确「符号已生成，本版本尚无该项经核对的文本解读。」两条本站中性反思模板不模仿诗节，不拼接两列主题作传统判词，不补作吉凶或ire／ibi。本项无方向、评分或主题投票。16图式表与专门朝向来源见[Ifá说明](IFA.md)。

## 掷筊·问事体验

以朝上的面判别：一平一凸为圣筊，两平为笑筊，两凸为阴筊。创建时冻结三对独立公平二值，四种数字组合中三类分别有2／1／1种；这是数字模拟分布，不是现实成功概率或真实器物的概率测量。

用户在揭晓前确认完整命题与单次／固定三次模式，保留否定和条件；确认后不改命题、模式或杯面。单次只揭第一对，三次模式必须揭完预定三对，三次均圣才满足本站可选条件，其他情况为「未获三次全圣确认」，不能写成三次全阴或自动重掷。笑筊为未明确答复，不等于反对。不补充命题也可文化演示，演示排除主题归纳；确认命题的象征回应也不能替代首页不同选项的方向判断。详见[掷筊与灼甲说明](JIAOBEI-ORACLE.md)。

## 灼甲观兆·历史体验

三个案例入口依据Smithsonian同一馆藏及教案的已核对内容，由用户主动选择，分别涉及雨、狩猎二十鹿的记录和问辞／判断／验辞的结构。不用问题关键词替用户选择，不把文物案例视为本次裂纹的判断，也不伪造古文字、原文或现代裂纹吉凶表。首次观察与案例在完成后冻结，未来只能追加最多20条带时间的实际结果，每条最多1000字；旧观察、旧解释和已有事后记录不可覆盖。本篇不参与主题或方向汇总，也没有AI判词。附件8.2的另一条龟甲／龟壳路线未实现。

## 场景与汇总

本地规则不对自由文本作语义识别。v1.2 移除类别，行动模式使用 2–10 个不同 options 字符串；提交前去首尾空白、校验非空及每项≤300字，保留否定和顺序。不为选项打分、投票或重新抽取，同一冻结结果用于逐项反思。新记录剔除 category；旧 category/action 和没有 options 的记录仍可恢复且不重算。

下面的单行动白名单说明旧版规则，新表单不再输入单一 action 或普通日常范围勾选；多选项的新记录始终不强造本地倾向，模型建议另行标注。

行动倾向仅在用户确认普通日常范围，且场景和**完整行动字符串**匹配下列白名单时启用：

| 场景     | 行动             |
| -------- | ---------------- |
| 上课安排 | 去上课           |
| 任务推进 | 开始整理任务清单 |
| 休息安排 | 安排十分钟休息   |
| 沟通联系 | 整理想表达的内容 |

这份表曾在旧版输入旁明示，保留用于理解旧记录；不可用模糊关键词匹配替代。未适配时「无明确倾向」；开放探索始终只汇总主题。提示或变化主题映射到象征倾向，阻力位不能当作建议。遇到主题张力保留不同视角。

汇总只接收已经冻结的单引擎结果。列出共同主题、各自侧重及推进／等待休整间的张力。行动倾向只在选定范围内各完成结果倾向完全相同时复述，不做多数票；否则无明确倾向。相关体系提示与参与范围一直可见。任何偏好都不能改变原始结果。

v2规则`summary-frozen-themes-v2`只比较原五套已完成结果的行动适配倾向。新增五篇全部排除方向参考；Ifá、灼甲及掷筊演示还排除共同主题、侧重和张力归纳，排除名单单独展示。地占各图、咖啡各标注、掷筊三轮各自属于一条结果，不能增加支持票数。只有新篇章或没有明确适配时显示无明确倾向，不填中性评分。

## 本地存储与离线

生日记忆是独立、自愿的本机偏好：只有用户点击「同意保存生日」后，`zhongbu-birthday-consent-v1` 才写入 `{version:1,consent:true,birthday}`。输入、提交、保存阅读或收藏都不会自动保存生日。下次初始化表单读取并校验，不把保存的生日合并到 Reading、分享、AI 请求或日志。修改字段不自动覆盖已保存生日；必须再次同意替换。用户可点击忘记，删除此独立键并清空表单。无效、未来或损坏记录不自动填入，读取不改写存储，存储失败提示后仍允许计算。

历史仅在「保存本次」或「收藏本条」事件写入 localStorage，收藏会保存其所在完整记录以保留上下文。已主动保存的记录会同步后续偏好。未保存当前结果只进入 sessionStorage 用于本标签页刷新恢复。Zod 对恢复数据逐项校验；损坏历史不自动覆盖。关闭标签页后未保存记录可能被清理，也可能被浏览器的会话恢复保留。

生产构建包含全部知识、算法、字体，无动态知识请求；Service Worker 预缓存构建资源。资源完成初次缓存后支持离线刷新。首次打开仍需要下载静态资源。缓存按站点 scope 和内容摘要分组，不清理其他项目缓存；更新在旧标签页关闭后生效。忽略静态文件响应的 Vary（开发预览服务器会附带 Origin），避免 CORS 取资源模式差异导致离线错失缓存。

十个篇章的本地流程不上传文本、生日或遥测，没有账户、支付或远程历法。用户主动提交的意见反馈存入私有 D1，防刷状态存入 Durable Object；它们不参与抽取、历法、解释或本机历史。原五套的可选模型延伸、反馈范围和保留规则见下文。GitHub Pages 和 Cloudflare 托管平台可能处理普通访问日志；本站不能控制平台自身日志。外部来源链接仅在用户主动点击时导航，站内算法不会访问它们。不同域名、浏览器和设备的本机历史及生日记忆互不共享。

## 独立的 AI 延伸（用户在 v1.1 授权新增）

本节只适用于原有塔罗、周易、梅花、数字和卢恩。新增地占、咖啡、Ifá、掷筊及灼甲不调用模型；前端请求构造器拒绝新体系，服务端AI契约仍只接受原五个ID。反馈契约接受十个ID，与AI权限无关。

`已完成且冻结的单体系结果 → 前端白名单构造 → 用户主动点击 → Pages /api 网关 → Service binding → Cloudflare Worker → DeepSeek → 单独的 enhancements 字段`

原始 Reading 与所有本地解释保持不变。服务器不参加抽取／历法／规则汇总，模型回复也不成为其他引擎的输入。每条回复保留实际模型名、提示版本、生成时间和发送上下文，跟随用户主动保存的记录。生成成功后不提供自动重写；要重新探索需明确建立新记录。

v1.2 起点击模型按钮默认发送问题、完整选项、所选一家结果、已有释义及模式／场景／目标日期，不发类别。v1.3 依用户要求移除按钮旁发送提示，发送范围仍在方法页与README公开；已移除的场景反思不再进入新请求。底层 includeContext=false 兼容旧调用，仍排除问题、行动、选项及反思；旧记录不变。不发送生日字段、问卜精确时刻、其他引擎与偏好。新数字九宫格只带精选象征主题与冻结释义，不带全部格数、缺位集合或生日数字串；旧个人日只带最终派生数字。梅花只带卦象与体用，不带年月日時换算轨迹。用户自行写在问题或选项中的私人信息仍会随这些自由文本发送。

模型对主动点击发送的问题进行语义理解，文案独立标为 AI，可能出错。当前提示词为 `zhongbu-single-engine-2026.09.30-11`。一次JSON模式调用返回用户可见的短解析、paragraphs依据索引、建议类别、所选选项索引、完整行动和一个执行安排；不要求推理草稿。先说明具体结构的联系，再给与之对应的行动，不反问。Worker验证依据无重复、不越界且至少两条（不足时用实际数量），行动模式的日常建议必须选有效options索引，显示选项原文以保留否定；事实核验／专业边界不强选选项。对外AiResponse仍为「解析＋建议」两段纯文本，目标100–200字。JSON或引用非法时失败，不重试、不用固定结论兜底；这些结构检查不能保证释义或建议语义正确。

Worker仅向上游发送本家methodVersion、rawSummary、paragraphs和traditional，省去共用概括headline/themes与已淘汰的reflection；系统提示为公共约束加本家专属规则，无其他家的结果、建议或历史消息。公共提示内一对合成聚会示例只说明不同依据可以支持参加或退出，不是当前抽取结果，也不是评测的人工诊断牌阵。允许有依据的相同方向，不读取其他回复来刻意制造差异。原始记录及本地解读保持不变。

各体系保留自己的依据结构：塔罗使用牌位和正逆，不把阻力当建议、逆位不一律负面；卢恩使用三位置作用；周易并列本卦、实际动爻与变卦，无动爻不另造变化；梅花结合实际动爻和简化体用；新数字九宫格只使用已经提供的精选主题，不猜生日、不补算次数、缺位或个人日，旧个人日记录仍以个人日为主、其他派生数字为背景。矛盾存在时解释为何更侧重其中一项，不能修改冻结结果来统一结论。象征支持的是模型对日常行动的建议，不能被写成已核实的事实、他人内心或专业判断。

仍使用800 token上限、非思考模式、服务端 `deepseek-flash`，不是Pro。截至2026-09-29的[官方型号页](https://api-docs.deepseek.com/quick_start/pricing/)映射为DeepSeek-V4.1-Flash，Pro为独立的DeepSeek-V4-Pro-0813。本次没有训练或微调权重，不人工截断完整回复；上游因长度终止的半答仍作为失败处理。保留否定词、不改抽取、不虚构经文、不提供高风险行动或政治推荐、不恐吓灾祸。提示词不是正确性保证。显示为纯文本，不执行返回的代码或HTML；既有成功回复保留当时的提示版本和原文。

普通日常选择对称评估：不能仅凭措辞把暂停／拒绝／休整定性为懒惰、逃避或不负责任；支持休整的结构可对应暂不参加，推进也可对应执行拒绝，不能一律映射成出勤或接受。不固定答可以或不可以；解析支持目标时段暂停时，不能把暂停挪到原安排结束之后。建议保留完整行动及否定对象；未明示长期范围时按目标日当日理解，明确长期的问题也不得偷缩。模型不是校方／单位许可，不编造假期、出勤规则、处分或用户疾病。这个约束只影响可选模型建议，不改变本地场景规则或原始抽取。实际遵守程度见[验证记录](VALIDATION.md)；评测使用未筛选随机组及独立诊断，不要求方向配额。

## 动画与简化呈现

提交过场约2700ms，支持跳过／Escape／减少动态效果；模型等待动画随请求开始与结束，秒数只显示真实等待时长。结果装饰使用确定性 SVG／CSS，无随机数、网络或计算副作用，支持统一暂停。刷新与历史恢复不重复提交过场。依据、原文、过程和来源继续冻结在记录与导出中，原五套结果卡按既有设计简化详情；新篇章保留理解方法必需的推演、来源、缺失资料和限制。动效不改变上下爻、正逆位或原始数据。

每个体系单独一页；顶部页签与下一家按钮切换当前篇章，手机下一家按钮在卡片右下。「查看全部」保留并排／纵向比较入口。翻页不重算、不改变偏好汇总范围或抽取结果。v1.6塔罗亲选时在原槽位翻出实际牌面，去掉选择顺序的1/2/3标记，保留位置含义；周易双面钱币腾空翻转后落地回弹震动，分六轮揭示；卢恩先摸袋再撬石。梅花与数字仍在提交时计算并冻结，新记录的engineRevealed从空集合开始，点击落梅／旋转九数轮盘后才显示卦象／生日矩阵及其解读。部分进度写入会话，主动保存后同步历史。v1.5或更早已显示的记录不强制重播。

原五套独立完成后开放自身AI入口，新增五篇没有该入口；所选可用体系全部完成后才开放汇总与导出，pending 塔罗或新篇章不算已完成。失败或缺生日项保留状态但不阻塞。点击有同步锁，动画完成／跳过／减少动态只允许一次回调；离开组件清理计时器。父组件按 readingId 和体系设置实例 key，并核对回调所属记录，避免旧动画推进新记录。周易与卢恩进度通过纯函数更新，其冻结 Reading 不变；塔罗仅在第三张实际选择时进行前述一次完成操作。新篇章按本节前述独立状态机记录操作，暂停或动态偏好变化不能产生第二次结果。

## 同源连接、反馈与防刷

Cloudflare Pages 入口通过同源 `/api/interpret` 和 `/api/feedback` 请求网关，再以 [Pages Service binding](https://developers.cloudflare.com/pages/functions/bindings/) 连接 Worker，保留原 Origin 和平台可信来源 IP；浏览器无需直连 workers.dev。GitHub Pages 可配置对应 Pages 绝对接口地址。该路径消除了浏览器对 workers.dev 的依赖，但没有中国境内多运营商网络验证或自有域名，不能保证 pages.dev 或 GitHub Pages 在中国所有网络可达。网络错误不会影响本地算法。

结果末尾的反馈由用户主动提交。`POST /feedback` 使用严格白名单：意见类别、5–2000字内容，可选当前体系和应用版本；只有用户主动勾选才附上本次问题，默认不附带。接口不接受生日、完整 Reading、原始 IP 或偏好，不调用模型。用户自行写在反馈或问题中的个人信息仍可能被保存，不能仅凭结构校验自动识别和清除。

2.0反馈体系白名单扩充为十个ID。`0002_feedback_experiences.sql`以复制旧行后重建表的方式扩充D1的CHECK约束，保留原字段、回执和接收时间。已有生产数据库必须先导出私有备份、核对备份与数据库条数，再迁移并核对条数及约束，最后部署新Worker；迁移失败或数目不符时停止部署并调查，不能清空反馈重建。命令见[Worker说明](../worker/README.md)。

反馈内容、UUID 回执与接收时刻存入私有 [Cloudflare D1](https://developers.cloudflare.com/d1/)，没有公开读取或管理接口。只有数据库写入成功才返回成功回执，失败保留表单。活动数据库约保留90天，每日 UTC 03:17 定时删除早于90天的行；平台备份与恢复保留政策由 Cloudflare 控制。管理员使用 `worker/scripts/feedback.mjs` 在授权本机查看、导出或删除；导出放在 Git 忽略的 `.wrangler/private-feedback/`，不得随网站或源码公开。模型内容不会因该数据库存在而自动归档。

防刷使用 [SQLite Durable Object](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)，以 Cloudflare 可信 `CF-Connecting-IP` 经独立服务端密钥 HMAC 得到的不可直接读出原 IP 的键路由。事务记录同一键在滚动60秒窗口内访问已知API的有效来源 POST 尝试；无效正文、业务校验失败及成本额度拒绝也计数。**第61次起限制在线API24小时**，返回「疑似脚本刷请求」提示及精确解封时间，期间重复请求不延长封禁，不在午夜提前清零。到期状态由 alarm 清理；缺绑定、密钥或存储异常时拒绝在线请求，不绕过检查。

这里用出口 IP 近似用户，HMAC 标识不是独立自然人身份或匿名化保证：校园、公司或家庭共用出口时共享额度；换 IP、代理和分布式脚本仍可能绕过单一身份限制。计数不依赖可清除的浏览器ID，刷新或清空本机记录不会解封。静态文件和本地占卜不计入API限额，封禁也不影响本地计算。

另外保留模型每IP滚动6次／分钟、反馈每IP3次／分钟和10次／24小时的成本限额；第7次模型请求只返回普通限流，不直接封一天。Cloudflare 原生节点限流还提供每IP6次、共享40次／分钟保护，但共享限制是节点近似值，不能作为全球账单硬上限。CORS 是浏览器来源约束，不是身份认证。配置、管理命令与成本边界详见 [Worker说明](../worker/README.md)。
