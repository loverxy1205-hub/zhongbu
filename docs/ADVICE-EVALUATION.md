# 单体系建议的固定样本评测

这个工具用于核对：同一道日常选择题，在不同实际牌阵下，建议是否解释了相应的牌位、正逆与结构，而不是一见「翘课」「不去」就固定否定。它不是预测有效性测试，也不设定「必须有多少条答可以」的目标。

`scripts/evaluate-advice.mjs` 默认只显示帮助，不发请求、不读取任何密钥。`generate` 仅在本地复用生产源码；只有显式 `sample --send` 才调用给定的公开代理端点，可能消耗模型额度。脚本不调用模型供应商接口，不自动获取或读取平台凭据。

## 生成一次，供版本间复用

在仓库根目录、安装锁定依赖后执行：

```sh
node scripts/evaluate-advice.mjs generate --run school-skip-20260930 --date 2026-10-01
```

默认问题为「我明天可以翘课嘛？」、开放探索、无预设场景。日期未指定时，取所选时区的明天，默认时区 `Asia/Shanghai`。可完整指定问题及行动选项，例如：

```sh
node scripts/evaluate-advice.mjs generate --run school-action --date 2026-10-01 --mode action --scene 上课安排 --question "我明天可以翘课嘛？" --option "明天去上课" --option "明天不去上课"
```

生成结果位于 `.wrangler/advice-evaluation/<run>/fixtures.json`，整个 `.wrangler` 已被 Git 忽略。保留：完整问题、模式、场景、选项顺序、否定、目标日期、时区、实际三张牌、生产构造的完整请求、生成时间、源提交号与样本 SHA256。没有生日字段。

每个批次包含：

- **10 组随机样本**：连续调用生产 `drawTarot(true, cryptoWord)`，从完整 78 张牌无放回抽三张，依次为现状／阻力／提示；每张独立 50% 逆位。Web Crypto 与拒绝采样沿用生产实现。不看牌后筛选、替换或补抽，同张牌可以出现在不同独立牌阵中。
- **2 组独立诊断对照**：一组为皇后逆位／阻力战车逆位／提示宝剑四正位，另一组为皇帝正位／阻力倒吊人逆位／提示战车正位。它们用于检视休整与推进结构是否有区别，不能混进随机统计，也不预定某个正确结论。

取样使用完整牌库的部分 Fisher–Yates，和从随机洗好的 78 张牌中选三个不同固定槽位具有相同分布。这里不模拟点击动画，也不读取任何现有用户记录。解释与请求直接使用 `interpret`、`buildAiRequest`；本地打包工具沿用已安装的 Rolldown，不引入新依赖。

同名 `run` 已有样本时拒绝覆盖。比较提示版本必须使用同一份 `fixtures.json`，不能看到旧版答案后重新抽牌，也不能只留下符合预期的回复。需要调查另一种问法时可另建批次，必须连同该批次全部结果一起说明。

## 显式采样公开接口

例如采样旧提示版本：

```sh
node scripts/evaluate-advice.mjs sample --send --run school-skip-20260930 --phase baseline --group all --endpoint https://zhongbu.pages.dev/api/interpret --origin https://zhongbu.pages.dev --expect-prompt zhongbu-single-engine-2026.09.30-9
```

新版本部署后，对同一份样本换一个 `phase` 名再运行。`--expect-prompt` 应填写实际计划部署的完整版本号，避免误将旧缓存、错误端点或未更新的部署视为新版本。工具不修改请求来暗示期待的肯定／否定答案。

默认 `--group random` 只发 10 条；`diagnostic` 只发 2 条；`all` 发 12 条。即使一起发送，报告仍将两类分开。默认请求起点至少间隔 12 秒，低于单 IP 每分钟 6 次；只允许通过 `--interval-ms` 增大间隔。全工具目录共用锁与上次请求时间，避免并行脚本累加请求；其他客户端的同网使用仍可能共享服务端额度，工具不绕过限流。

每次发请求前先写入 `in-flight` 记录，再调用公开端点。结果保存在 `<phase>.json`，逐次原子落盘，包含样本 ID、请求哈希、时间、HTTP 状态、响应原文、可解析 JSON、模型名、提示版本和失败原因。HTTP 错误、超时、无效响应、网络错误、版本不符全部保留，不过滤、不自动重试。遇到 429 或提示版本不符停止整批，其余失败也会记录，最后返回非零退出状态。

Ctrl+C 会取消当前请求并记录状态。继续时重复同一命令，已尝试的样本一律跳过，包括失败、取消或强制终止后残留的 `in-flight`，防止无法确认上游是否收费时自动重复。恢复时必须保持端点、Origin、样本哈希、组别、版本与间隔一致。强制杀死进程可能留下 `.sampling.lock`；确认该进程确已退出后才可手动移除锁，不能删除已记录的请求来制造重试。

所有尝试保留不等于所有请求成功。报告中将失败计入实际尝试数；未完成样本单独说明。若确需另做重复实验，应新建有明确理由的阶段名，保留旧阶段，不以新结果替换旧结果。

## 离线报告与人工核对

```sh
node scripts/evaluate-advice.mjs report --run school-skip-20260930
```

报告不联网，列出每个阶段、每类样本的计划数／实际尝试数、状态计数、实际模型与提示版本，并核对样本哈希。它不根据「可以」「不要」几个词自动分类，也不输出准确率。应逐条并排读取固定问题、实际牌阵与完整回复，记录：

1. 是否保留用户所问的完整行动、否定、一次性／长期范围与明确日期。
2. 是否确实用到当前牌位及正逆，尤其没有把阻力位的牌直接当行动建议。
3. 建议方向是否来自这次结构，还是套用「都应上课／都应坚持」的预设结论。
4. 是否给出清楚但不过度保证的具体建议，是否凭空添加生病、疲劳、处罚、许可、年龄或他人心理等现实事实。
5. 休整与推进诊断是否表现出合理差别；若结论相同，理由是否足够解释，不能为制造差异强迫相反答案。

十组小样本只能展示这一批的实际行为，不能推断总体比例或证明问题永远解决。对外报告必须同时写明随机样本、人工对照、失败数量及剩余偏差。这个工具是测量手段，不是训练权重，也不改写已保存的历史回复。

2026-09-30的实际版本对比、新随机批次及跨体系协议结果见[验证记录](VALIDATION.md)，全部57条可见回复及其白名单输入见[公开评测JSON](evaluations/advice-20260930.json)。这份公开数据只包含本题与合成测试，不能将本机私有记录或反馈按同一方式自动发布。
